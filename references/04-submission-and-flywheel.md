# 阶段 5 · 投稿套件打包、审稿梗概与投稿反馈飞轮

好稿件如果直接扔一份无头无尾的裸 `.txt` 过去，编辑往往懒得从第 1 行自己找卖点；如果投了一家拒稿就放弃，也跑不出小程序分销的概率优势。

---

## 一、高点击投稿书名四类公式

写完 `manuscript.txt` 并通过质检后，从 `story_bible.json` 中结合完稿爽点提炼 **3–5 个备选书名**（长度控制在 **8–18 汉字**，一眼看懂谁被欺负、怎么反杀），最终择一作为 `picked_title`：

1. **物证 + 反差动作型**：《把陪嫁金镯喂狗后，婆婆跪求我复婚》
2. **期限倒计时 + 身份切割型**：《离婚冷静期最后一天，他在给白月光办满月酒》
3. **原话奉还打脸型**：《他说离了他我活不起，转身我买断他厂里订单》
4. **具体数字 + 血泪账单型**：《替丈夫还债六年，我翻出他写给弟媳的赠与书》

> 忌讳：抽象诗意书名（如《暮色渐沉》《那年烟火》《念念不忘》）——小程序信息流用户不会点开这种名字。

## 二、严禁混淆「投流导语」与「编辑审稿梗概」

填写 `submission_meta.json` 时，这两段文字承担完全不同的商业职能，必须分开撰写：

| 字段 | 受众 | 字数 | 写作铁律 |
| :--- | :--- | :--- | :--- |
| **`hook_text`**（投流导语） | 刷抖音/微信的小说付费读者 | 贴近对标导语（通常 200–450 字） | 制造极致情绪缺口与悬念，**绝不剧透大结局**。 |
| **`editor_synopsis`**（审稿故事梗概） | 日审数百封邮件的收稿编辑 | 250–400 字 | **必须剧透全书结构**：写清 ① 开篇核心矛盾 → ② 第 40% 处付费卡点事件 → ③ 主角底牌与反杀链路 → ④ 最终结局走向（如离婚独美/反派破产入狱）。 |

## 三、一键导出标准投稿 `.docx` 套件

### 3.1 准备 `submission_meta.json`

保存在当前稿件项目目录下：

```json
{
  "picked_title": "选定主书名",
  "title_candidates": ["备选1", "备选2", "备选3"],
  "genre": "追妻火葬场 / 婆媳世情",
  "target_audience": "三四线城市 30-40 岁女性",
  "author_pen_name": "笔名（未指定可填作者）",
  "paywall_chapter": 4,
  "hook_text": "选定的完整投流导语正文……",
  "editor_synopsis": "含卡点、底牌与明确结局的250-400字编辑审稿梗概……"
}
```

### 3.2 运行打包脚本

```bash
python3 <skill_dir>/scripts/submission_packager.py package \
  --project-dir "<项目目录>" \
  --mark-paywall
```

生成产物（位于 `<项目目录>/submission/`）：
- `《书名》_编辑审稿版(标卡点).docx`：前置书名、备选书名、题材、实测字数、导语、含结局审稿梗概，并在第 `paywall_chapter` 章末尾自动插入醒目的 `【★ 建议付费卡点位置】` 分割标线，极大降低编辑审稿阻力；
- `《书名》_纯净正文版.docx`：标准四号字体、1.5 倍行距、首行缩进排版，仅含章节与纯净正文，方便直接复制进平台后台；
- `email_pitch.txt`：可直接复制进 QQ 邮箱发送的自荐正文与标准化邮件标题。

### 3.3 实操投递避坑提醒（写入交付提示）

1. **邮箱选择**：98% 的小程序收稿编辑使用 QQ 邮箱，尽量使用**高权重老 QQ 邮箱**投递；同一天不要用新邮箱高频群发几十家，避免进垃圾箱。
2. **广撒网概率分布**：全网收小程序短篇的工作室达 200–300 家，各家缺稿题材档期不同；一轮投递需有系统台账追踪，不要投了 3 家没回音就自我否定。
3. **人工终读 3 分钟**：发邮件前请用户亲自默读一遍导语与前 4 章，把明显别扭的口语微调顺口。

## 四、投稿台账与选题复利飞轮

工作区默认维护一份 `投稿台账.csv`（Excel/WPS 可直接双击打开）和 `投稿台账.md` 摘要视图：

1. **每次投递登记**：
   ```bash
   python3 <skill_dir>/scripts/submission_packager.py track add \
     --title "<书名>" \
     --genre "<题材>" \
     --hook-strategy "<导语策略>" \
     --han-count <实测汉字数> \
     --channel "<投稿平台/编辑邮箱或工作室名>" \
     --status "待审" \
     --notes "<备注>"
   ```
2. **收到回复后更新状态与拒稿原因**：
   ```bash
   python3 <skill_dir>/scripts/submission_packager.py track update \
     --id 1 \
     --status "过稿保底" \
     --notes "保底800+50%分成，编辑夸第4章卡点切得准"
   ```
   允许状态值：`待审`、`拒稿`、`过稿保底`、`分成起量`。
3. **统计复盘各策略过稿率**（指导下一轮导语抽卡该偏重哪种策略）：
   ```bash
   python3 <skill_dir>/scripts/submission_packager.py track stats
   ```
