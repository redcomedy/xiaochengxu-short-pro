# 阶段 3 & 4 · 动作流行文、黄金四千字盲审与完稿扩写

在没有验证「前 4,000 字具备买量付费张力」之前，严禁直接一口气扩写完后 9,000 字。

---

## 一、小程序短篇动作流行文 6 大铁律

目标受众习惯竖屏手机碎片阅读，阅读耐心极短：

1. **短句快切排版**：每段叙述 1–2 句（单段一般不超过 60 汉字）；动作/神态独立成行；对话独立成行。
   ```text
   01

   我把离婚协议推到他手边。

   他没看，继续剥桌上的虾。

   "林晚，差不多得了。"

   "三万块彩礼我没要，现在这套房子首付是我妈卖菜攒的。"

   "夫妻一场，别算这么清。"
   ```
2. **高对话密度（55%–75%，黄金区 60%–70%）**：把背景、冲突、筹码和反击尽量塞进角色的嘴里。能用一句硬对白刺破的，不要用第三人称叙述转述。
3. **零环境描写，用道具与动作替代情绪**：
   - 不写天气、装修、夜景、氛围渲染；
   - 不贴抽象情绪标签（写 `我把她发来的语音一条条拉黑，删到第 47 条时手抖了一下`，不写 `我心如刀割`）。
4. **严格第一人称（`我`）与微自嘲基调**：
   - 严禁突然跳出 `我` 的视听范围去描写反派背地里在想什么（只能通过对方事后露馅、微信误发、录音或第三方转述得知）；
   - `我` 的连续内心独白最多 2 句，略带清醒的冷幽默或自嘲，避免苦情怨妇哭天抢地；
   - 章节末尾直接硬切下一章编号，不做“这件事让我明白了一个道理”的说教总结。
5. **单场冲突 3–5 级阶梯拆解**：
   - 禁止“反派骂一句 → 主角反手亮身份 → 全场跪下”的速朽爽感；
   - 重要交锋拆成 **试探 → 嘲讽 → 揭短 → 威胁 → 撕破脸**，每级必须冒出一条**新信息或新筹码**；一方撂狠话后，另一方先给一个 10 字以内的微妙停顿动作再回击。
6. **每 2–3 章一句截图级反差金句**：不靠排比说教，靠期待与现实的精准落差（如 `他说最怕我吃苦的时候，正用我的副卡给别人挑手镯。`）。

## 二、双层科学禁词门禁

配合 `scripts/manuscript_linter.py` 强制执行，避免过度一刀切造成语句残缺，同时彻底清除 AI 腔与悬浮腔：

### Tier-1 硬门禁（必须 0 命中）

- **AI 烂俗动作套话**：`嘴角+勾/扬/撇/抽/沉/掀`、`眼中/眼底/目光+闪过/掠过/透着+一丝/一抹`、`心中/心里+泛起/涌起/一紧/一沉/一痛`、`像/如同+重锤/炸雷/利刃/冰窖/晴天霹雳`、`空气/时间/气氛+凝固/凝滞/静止/窒息`、`深吸一口气+缓缓/慢慢`、`带着一丝/一抹/一股`、`这不是……而是……`、`五味杂陈`、`面面相觑`、`不可置信`、`不容置疑`、`戛然而止`、`瞳孔地震`、`死寂`。
- **受众疏离词**：`轧机`、`离岸信托`、`对赌协议`、`共患神经` 等。

### Tier-2 密度管控词（全篇每千汉字合计 ≤ 1.5 次）

`顿时`、`立刻`、`连忙`、`瞬间`、`渐渐`、`不断`、`再次`、`十分`、`果然`、`猛地`、`显然`、`似乎`、`仿佛`。允许在自然口语中偶发，绝不允许成堆出现暴露机器感。

## 三、阶段 3 · 黄金前 4,000 字小样门禁 + 独立毒舌编辑盲审

### 3.1 写第 `1` 至 `K` 章（至付费卡点章悬崖处）

1. 将第 `1` 至 `K` 章正文写入 `manuscript.txt`（纯正文，不含书名、梗概和说明，章标格式统一如 `01` 或 `第一章` 独占一行）；
2. 同步更新 `story_bible.json` 中各角色 `current_status` 及前 `K` 章已触发道具状态；
3. 运行小样静态质检：
   ```bash
   python3 <skill_dir>/scripts/manuscript_linter.py "<项目目录>/manuscript.txt" --mode sample --expected-chapters <K> --paywall-chapter <K> --output "<项目目录>/sample_lint_report.json"
   ```
   若退出码非 `0`，按报告提示直接修改至 `status == "pass"`。

### 3.2 启动「毒舌收稿编辑」独立盲审

**核心原则：作者自己审自己永远偏心。** 在支持子智能体的环境中（如 `invoke_subagent`，选用只读 `research` 类型），必须新开一个**干净隔离的上下文**，**禁止向其透露 `outline.md`、写作意图或后续洗白计划**，仅将：
- `cards.md` 中选定的导语正文；
- `manuscript.txt`（前 `K` 章小样）；

交给该子智能体，指示其扮演**「每天审 300 封稿件、极其苛刻的小程序买量主编」**，按以下 5 项（各 20 分，满分 100 分）逐条打分、给出毒舌批注与必须修改的具体行段：

| 盲审维度 | 满分 | 主编秒拒/拉黑判定标准 |
| :--- | :--- | :--- |
| **1. 首屏抓力（前 300 字）** | 20 | 前 300 字是否还在交代人物生平或慢热铺垫？ |
| **2. 导语咬合度** | 20 | 导语最后一句与第一章第 1 段之间有没有剧情断层或人设割裂？ |
| **3. 下沉代入与去 AI 味** | 20 | 30–40 岁三四线女性读不读得懂、共不共情？台词有没有翻译腔或书生气？ |
| **4. 憋屈与隐忍合理性** | 20 | 女主前期不反击有没有硬性现实约束？反派使坏是不是落到了具体的钱、房、名分？ |
| **5. 第 `K` 章付费卡点逼单力** | 20 | 停在最后 3 行时，读者会不会心痒难耐想立刻充 9.9 元解锁第 `K+1` 章？ |

### 3.3 返修与停等确认

1. 将盲审评分、逐条批评与改稿动作记入 `blind_audit_report.md`。
2. 若总分 `< 80` 或任意单项 `< 15`，**自动依据盲审意见改写前 `K` 章并复跑 `manuscript_linter.py --mode sample` 直至达标**。
3. 更新 `00_state.json`（`stage: "sample_audit"`），向用户展示：黄金前 `K` 章关键卡点效果 + 盲审评分摘要 + 小样质检数据。**停等用户确认小样方向无误后，再开启阶段 4 扩写。**

## 四、阶段 4 · 账本制完稿扩写与全维度质检

### 4.1 逐章扩写与账本核销

写第 `K+1` 至 `N` 章时，必须遵循：
1. **每章开写前读 `story_bible.json`**：确认主角伤病/手中筹码状态，以及本章要核销哪一条 `debts`（反派曾经说过的大话）。
2. **精准原话打脸**：第 2 章反派嘲讽过什么，翻盘章就用完全对称的证据和台词砸回去；打脸现场必须补上反派从**嚣张 → 错愕 → 恐惧**的表情动作演变，并在这一刻放出旁人震惊反应。
3. **写完一章即更新账本**：在 `story_bible.json` 中把已兑现的 `debts[i].status` 和 `props[i].status` 改为 `"resolved"`。
4. **注意 300 字薄场景法则**：某关键冲突写完如果只有两三百字，说明对方认输太快——加一层反扑或第三方补刀，别用废话硬凑。

### 4.2 续写截断协议

若单次输出因长度被截断，用户回复“继续”时：
- 先读取磁盘上 `manuscript.txt` 末尾最后 300 字与 `story_bible.json`；
- **从截断字符位置精确接续，不说“好的”，不写过渡回顾，第一个字就是故事正文**。

### 4.3 完稿硬门禁

最后一章写完并追加进 `manuscript.txt` 后，**必须执行全量质检**：

```bash
python3 <skill_dir>/scripts/manuscript_linter.py "<项目目录>/manuscript.txt" \
  --mode full \
  --expected-chapters <N> \
  --paywall-chapter <K> \
  --bible "<项目目录>/story_bible.json" \
  --output "<项目目录>/lint_report.json"
```

退出码必须为 `0`（`status == "pass"`），否则逐项修复后重跑，禁止口头宣称“已检查通过”。随后将 `00_state.json` 置为 `stage: "full_draft"`。
